# Heart Sound DSS Project - Complete Reference Guide

## 1) Project Purpose

This project builds a Decision Support System (DSS) for heart health analysis from phonocardiogram (PCG) data.

At a high level, the pipeline does the following:

1. Reads heart sound recordings (.wav) from the PhysioNet 2022 training set.
2. Converts each recording into a chromagram image.
3. Extracts deep features from images using pre-trained CNN backbones.
4. Runs machine learning models for either:
   - unsupervised anomaly screening, or
   - supervised classification with cross-validation.

The repository contains two main analysis tracks:

- main.py: unsupervised anomaly-oriented flow.
- heart_health_dss.py: supervised, evaluation-heavy research flow.

## 3) End-to-End Data Flow

### Stage A: Audio to Image

Script: generate_cgram_modified.py

Input:
- training-2022/training-2022/*.wav

Process:
1. Loads each .wav with librosa.
2. Computes chroma_stft representation.
3. Saves a clean image with minimal margins.

Output:
- chroma-2022/*.jpg

Why this stage matters:
- CNN backbones (VGG19/MobileNetV2) expect image input, so PCG audio is transformed into a visual time-frequency representation.

### Stage B1: Unsupervised Screening

Script: main.py

Input:
- chroma-2022/*.jpg

Process:
1. Loads VGG19 and MobileNetV2 (ImageNet pre-trained, feature extractor mode).
2. Extracts flattened deep feature vectors from both models.
3. Trains One-Class SVM and Isolation Forest on those feature spaces.
4. Combines 4 predictions via vote rule.

Output:
- dss_decisions.npy
- vgg_features.npy
- mobilenet_features.npy

### Stage B2: Supervised DSS

Script: heart_health_dss.py

Input:
- chroma-2022/*.jpg
- training-2022/training-2022/physionet_2022.csv

Process:
1. Loads images and maps labels from PhysioNet CSV.
2. Extracts VGG19 + MobileNetV2 features and concatenates.
3. Reduces dimensionality with IncrementalPCA (memory-safe).
4. Trains multiple classifiers with stratified cross-validation.
5. Reports metrics, confusion matrices, ROC curves.
6. Saves trained models and result files.

Output:
- results/features_raw.npy
- results/features_reduced.npy
- results/labels.npy
- results/roc_curves.png
- saved_models/*.pkl

## 4) Script-by-Script Explanation

## 4.1) generate_cgram_modified.py

Primary job:
- Build chromagram images from every .wav file.

Key implementation notes:
- Uses matplotlib non-interactive backend (Agg) for headless execution.
- Creates output directory automatically.
- Skips generating an image if the output file already exists.
- Keeps figure margins minimal for cleaner model input.

Typical run:
- python generate_cgram_modified.py

When to run:
- Run this first when chroma-2022 is missing or incomplete.

---

## 4.2) main.py (Unsupervised)

Primary job:
- Perform anomaly-oriented DSS without requiring ground-truth labels.

Pipeline summary:
1. Validates chroma-2022 exists.
2. Loads and prepares pre-trained CNNs.
3. Batch extracts features from all images.
4. Trains:
   - One-Class SVM on VGG features
   - One-Class SVM on MobileNet features
   - IsolationForest on VGG features
   - IsolationForest on MobileNet features
5. Applies vote logic and prints final counts.

Operational improvements already present:
- Timestamped log helper.
- Heartbeat logging during long estimator fitting.
- Batch progress bars for extraction.

Important behavior note:
- Current vote rule in main.py is highly sensitive:
  - If any model predicts anomaly, final output is Abnormal.
- This tends to produce abnormal-heavy outputs.

---

## 4.3) heart_health_dss.py (Supervised Research Flow)

Primary job:
- Full training/evaluation pipeline with cross-validation and saved models.

Major modules:
- Label loading:
  - Uses PhysioNet CSV as active source.
  - Supports standard/headerless 2-column fallback parsing logic.
- Image loading and validation:
  - Validates image readability.
  - Aligns labels to image names.
- Feature extraction:
  - VGG19 + MobileNetV2 deep features.
  - Feature fusion by concatenation.
- Dimensionality reduction:
  - IncrementalPCA to reduce memory pressure.
- Model training:
  - SVM, Gradient Boosting, HistGradientBoosting, RandomForest, AdaBoost.
  - Stratified cross-validation with fold adjustment if class counts are low.
- Evaluation:
  - Accuracy, Precision, Recall, F1, Sensitivity, Specificity, AUC.
  - Confusion matrix and ROC visualization.
- Persistence:
  - Saves .pkl models and result artifacts.

Resume and cache support:
- Supports resume stages via environment variable DSS_RESUME_STAGE.
- Uses cached .npy features/labels in results/.
- Can resume from reduced-feature stage or raw-feature stage.

## 7) Expected Runtime Characteristics

- Feature extraction with VGG19 on CPU is the slowest stage early on.
- One-Class SVM on large feature matrices can run for many minutes.
- Heartbeat logs in main.py are expected and indicate active progress, not freezing.
- Supervised flow can be long due to cross-validation over multiple models.

## 8) Result Interpretation Guide

### For main.py

Output is an anomaly-oriented vote result, not a clinical diagnosis.

Key caution:
- With current voting rule, abnormal counts can be inflated.
- Treat as screening output only.

### For heart_health_dss.py

Use these as your core quality indicators:
- F1 Score (balanced precision/recall)
- Sensitivity (ability to detect abnormal)
- Specificity (ability to avoid false alarms)
- ROC/AUC for ranking quality

Practical recommendation:
- Compare individual model metrics and ensemble performance, not only accuracy.

## 9) Common Issues and Fixes

Issue: Image folder not found
- Cause: chroma-2022 missing.
- Fix: run generate_cgram_modified.py.

Issue: Very long runtime appears stuck
- Cause: heavy CPU stages (VGG feature extraction, One-Class SVM fit).
- Fix: monitor logs; heartbeat messages indicate active computation.

Issue: Memory pressure during training
- Cause: very high-dimensional fused features.
- Fix: use/keep IncrementalPCA stage and cache-based resume in heart_health_dss.py.

Issue: Class imbalance effects
- Cause: dataset label distribution and model sensitivity.
- Fix: inspect confusion matrices and tune models; do not rely on a single metric.
